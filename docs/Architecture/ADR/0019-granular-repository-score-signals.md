# ADR-0019 — 저장소 점수 신호 세분화

- 상태: Accepted
- 기록일: 2026-09-19
- 결정 주체와 근거: 사용자의 검증축 21점 집중 지적과 전 축 세분화 요청, [Issue #47](https://github.com/SangJun-Pyo/MyAiScore/issues/47)
- 기록 성격: 구현과 함께 기록
- 대체 관계: [ADR-0017](0017-content-aware-repository-scoring.md)의 품질 공식을 v2.3 신호 집합에 맞게 조정하고 [ADR-0018](0018-evidence-aware-collaboration-profile.md)의 유형 입력을 새 신호 ID로 이전

## 배경

v2.2 검증축은 테스트 신호 하나가 최대 21/25점, 자동화축은 CI 하나가 최대 15/25점이었다. 내용 실질과 breadth를 보더라도 한 종류의 파일이 축 대부분을 결정해 사용자가 어떤 검증 습관을 갖췄고 무엇이 비었는지 설명하기 어렵다. 맥락과 기록도 재현 환경, 인터페이스 계약, 변경 책임처럼 AI가 안전하게 작업할 때 유용한 신호를 구분하지 못했다.

## 결정

새 분석은 `repository-signals-v2.3`을 발급한다. 네 축과 축별 25점·총 100점 상한은 유지하되 다음처럼 세분화한다.

| 축 | 신호와 최대점 |
|---|---|
| 맥락 | README 5, 협업 지침 5, 문서 4, 메타데이터 3, 인터페이스 계약 4, 재현 환경 4 |
| 검증 | 실행 진입점 4, 테스트 내용 5, 테스트 분포 4, 실패·경계 사례 4, 정적 검사 4, 커버리지 게이트 4 |
| 기록·추적 | 변경 기록 6, 결정 7, 템플릿 4, 마이그레이션 3, 변경 책임 4, 커밋 설명 4 |
| 자동화 | CI 테스트 5, CI 품질 검사 5, 의존성 4, 배포 4, 작업 도구 4, 환경 구성 3 |

테스트 내용은 지원 언어의 고유 선언·assertion을, 실패·경계 사례는 오류·예외·잘못된 입력 단서를, 테스트 분포는 비어 있지 않은 지원 테스트와 `scanned_tree`의 소스 대비 비율을 함께 본다. 같은 내용 해시의 테스트 파일은 실질·분포·경계 신호에서 한 번만 센다. CI 테스트와 CI 품질 검사는 같은 워크플로를 읽을 수 있지만 서로 다른 실제 명령 종류를 요구하며, 배포 전용 workflow에는 해당 신호의 presence 자체를 부여하지 않는다. 기본 manifest의 `no test specified` placeholder도 실행 진입점으로 인정하지 않는다. 실제 실행 성공은 여전히 주장하지 않는다.

세분화로 하나의 파일이 여러 의미 신호의 경로가 될 수 있으므로 v2.3 존재 바닥은 10%로 낮춘다.

```text
quality = presence × (0.10 + 0.65 × substance + 0.25 × substance × breadth)
```

빈 파일은 substance와 breadth 결합 보상을 받지 않는다. 검증·자동화의 단일 신호 최대점은 5점이다.

기록·추적은 조건부 마이그레이션을 포함한 원시 최대점이 28점이고 축에서 25점으로 제한한다. 따라서 DB가 아닌 저장소도 마이그레이션 없이 다른 기록 신호로 25점에 도달할 수 있다.

## 호환과 안전

schema는 `repository-report-v2`를 유지한다. strict parser는 rule version별 신호 순서·배점·품질 공식을 선택하며 기존 v1, v2.1, v2.2 저장 결과를 소급 재계산하지 않는다. 계약·환경·CODEOWNERS 같은 파일도 기존 경로 검증, 크기 제한, 마스킹, 저장소 코드 미실행 경계를 그대로 따른다.

## 대안과 결과

- **검증 21점만 낮추기:** 다른 축의 CI 집중과 새 후보 신호를 설명하지 못해 전 축을 함께 정리했다.
- **새로운 다섯 번째 축 추가:** 100점 의미와 코호트를 다시 설계해야 하므로 재현성·계약·책임을 기존 네 축의 작은 신호로 먼저 검증한다.
- **테스트 실행·커버리지 실제 측정:** 제출 저장소 코드를 실행하는 신뢰 경계를 넘으므로 제외한다.

신호 설명력은 좋아지지만 정규식 기반 정적 관찰이라는 한계는 남는다. 20개 블라인드 순위와 50~100개 코호트에서 신호 상관·포화·언어 편향을 확인한 뒤 배점을 다시 바꿀 경우 rule version을 올린다.
