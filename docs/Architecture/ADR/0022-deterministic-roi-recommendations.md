# ADR-0022 — 결정론적 ROI 개선 조언과 코호트 표시 보류

- 상태: Accepted
- 기록일: 2026-09-19
- 결정 주체와 근거: 우선순위가 분명한 세부 개선 조언과 투명한 비교 기준에 대한 사용자 요청, [Issue #55](https://github.com/SangJun-Pyo/MyAiScore/issues/55)
- 기록 성격: 구현과 함께 기록
- 대체 관계: [ADR-0017](0017-content-aware-repository-scoring.md)의 단일 최저축 도전을 v2.6에서 확장한다. 코호트 보류 조건은 [ADR-0023](0023-fixed-sha-reference-cohort.md)에서 충족했다.

## 배경

v2.5는 가장 낮은 축 하나에 고정 조언을 붙인다. 같은 축 안에서 어떤 신호가 가장 적은 노력으로 실제 점수를 바꿀 수 있는지 구분하지 못하며, 이미 축 상한에 막혀 총점이 오르지 않는 행동도 추천할 수 있다. 참조 코호트 비교도 제안됐지만 현재 저장소에는 고정 SHA·점수·수집 조건을 함께 검토한 실제 공개 저장소 표본이 없다.

## 결정

새 분석은 `repository-signals-v2.6`을 발급한다. 각 측정 가능한 미충족 신호를 최대점으로 개선했다고 가정해 전체 네 축 점수를 다시 계산하고, 현재 총점과의 차이를 `gain`으로 사용한다. 신호별 작업량은 1~3의 고정 내부 상수이며 `gain / effort` 내림차순, gain 내림차순, 신호 정본 순서로 안정 정렬한다. 총점이 실제로 오르지 않는 행동, 미측정 신호, DB 의존성이 확인되지 않은 마이그레이션은 후보에서 제외한다.

공개 응답과 화면에는 내부 gain·effort 숫자를 내보내지 않는다. 최대 세 개의 신호 ID, 축, `quick | medium | large`, 이미 근거 카드에서 검증된 선택 경로 하나 또는 `null`만 보낸다. 한국어·영어 행동 문구는 신호 ID별 고정 템플릿에서 만든다. strict parser가 같은 재계산과 경로 연결을 수행하므로 순서·난이도·경로를 바꾼 응답은 거부한다. 기존 `nextChallenge`는 v1~v2.5 저장 이력 호환을 위해 유지한다.

v2.6의 `cohort`는 `null`로 고정한다. 50개 이상의 공개 저장소를 고정 SHA로 수집하고 rule version, 포함·제외 조건, 크기·언어 분포, coverage와 manifest digest를 함께 체크인하기 전에는 순위·백분위·등급을 표시하지 않는다. 작은 미검증 표본을 GitHub 전체의 상대 위치처럼 표현하지 않는다.

## 대안과 결과

- **최대 배점에서 현재 점수만 빼기:** 축 25점 상한 때문에 실제 총점 gain이 0인 행동을 추천할 수 있어 채택하지 않았다.
- **LLM 자유 생성 조언:** 더 자연스러울 수 있지만 비결정적이며 저장소 문구 주입과 검증 비용이 생겨 채택하지 않았다.
- **즉시 임의 백분위 표시:** 비교 근거가 없으므로 채택하지 않았다. 코호트 데이터가 준비되면 새 ADR과 rule version으로 활성화한다.

추천 순위는 점수 규칙 안의 행동 우선순위일 뿐 실제 개발 비용이나 프로젝트 가치를 측정하지 않는다. 경로가 있더라도 해당 파일의 결함을 단정하지 않으며, 저장소 코드를 실행하지 않는다.
