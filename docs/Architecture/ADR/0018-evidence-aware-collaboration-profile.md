# ADR-0018 — 근거 충분성에 따른 네 차원 협업 유형

- 상태: Accepted
- 기록일: 2026-09-19
- 결정 주체와 근거: 사용자가 승인한 저장소 점수 v2 후속 구현, [Issue #43](https://github.com/SangJun-Pyo/MyAiScore/issues/43), [`SCORING_V2_PROPOSAL`](../../Assessment/SCORING_V2_PROPOSAL.md)
- 기록 성격: 구현과 함께 기록
- 대체 관계: [ADR-0017](0017-content-aware-repository-scoring.md)의 점수·수집 규칙은 유지하고, 새 `repository-signals-v2.2` 결과에서 기존 여섯 스타일의 사용자-facing 역할을 대체

## 배경

기존 여섯 스타일은 총점 20점 미만, 균형 조건, 최고점 축 하나의 순서로 판정한다. 대부분의 결과가 최고점 축 네 종류로 수렴하고 점수 높낮이와 스타일 의미가 섞인다. 반대로 근거가 거의 없거나 수집이 불완전해도 반드시 하나의 스타일을 부여한다.

공유하기 쉬운 유형은 제품에 중요하지만, 저장소 신호만으로 사람의 성격이나 능력을 추론해서는 안 된다. 점수와 직교하는 상대적 배치를 설명하고, 자료가 부족하면 유형을 만들지 않는 계약이 필요하다.

## 결정

`repository-signals-v2.2`는 점수 공식을 바꾸지 않고 `repository-collaboration-profile-v1`을 추가한다. 네 차원은 다음과 같다.

| 차원 | 양쪽 | 관찰 근거 |
|---|---|---|
| orientation | D 기록형 / R 실행형 | 맥락·기록 축과 검증·자동화 축의 상대 비중 |
| workflow | H 직접확인형 / P 파이프라인형 | 테스트·검사·로컬 스크립트와 CI·의존성·배포 자동화의 상대 비중 |
| timing | S 설계선행형 / T 추적중심형 | README·지침·템플릿과 변경·결정·적용 가능한 마이그레이션 기록의 상대 비중 |
| shape | F 집중형 / E 균형형 | 네 축 최고·최저 차이 |

각 신호 묶음은 최대점 대비 획득점으로 정규화한다. DB가 예상되거나 실제 파일이 있는 경우에만 마이그레이션을 timing 분모에 넣고, API 가용성에 따라 유형이 달라지지 않도록 커밋 집계는 유형 입력에서 제외한다. 커밋 집계는 기록 점수 보너스로만 유지한다. 두 방향 차가 0.12 이하면 경계 근처로 표시한다. shape는 기존 균형 기준과 연결되도록 축 spread 6에서 양쪽 강도가 같아진다. 임계값은 코호트 교정 전 버전 고정 초기값이며 보편적 인구 분포를 뜻하지 않는다.

다음 중 하나면 네 글자 코드를 `withheld`한다.

- partial collection, tree truncation, selection limit 또는 테스트 형식 미측정
- 점수가 관찰된 축이 3개 미만
- substance 0.25 이상인 신호가 4개 미만
- 어느 차원의 양쪽 근거가 모두 0
- 둘 이상의 차원이 경계 근처

한 차원만 경계 근처면 결정론적인 동률 규칙으로 코드를 발급하되 화면에 경계 상태를 함께 표시한다. 유형 제목은 네 선택 라벨을 조합해 만들며 별도의 성격 캐릭터나 능력 등급을 붙이지 않는다.

## 호환과 검증

schema는 `repository-report-v2`를 유지하고 rule version으로 필드를 구분한다. strict parser는 기존 `repository-signals-v2.1` 응답을 계속 읽고, v2.2에서는 `collaborationProfile`을 신호 점수와 진단에서 다시 계산한다. 임의 코드·강도·보류 이유를 넣은 응답은 거부한다. `repository-report-v1`의 여섯 스타일도 저장 이력 호환을 위해 유지한다.

## 대안

- **기존 최고점 스타일 유지:** 유형 다양성과 점수 독립성을 확보하지 못해 새 결과의 주 유형에서는 제외했다.
- **16개 캐릭터 이름과 자유 카피:** 저장소 신호를 사람의 성격처럼 과장할 위험이 있어 네 글자와 설명 가능한 조합 라벨만 사용한다.
- **모든 결과에 강제 코드:** 공유성은 높지만 근거 부족 상태를 숨겨 제외했다.
- **코호트 중앙값을 즉시 임계값으로 사용:** 아직 투명한 참조 코호트가 없어 v2.2에는 넣지 않는다.

## 결과와 재검토 조건

점수와 유형의 역할이 분리되고, 불완전한 저장소에는 정직한 보류 상태가 생긴다. 반면 초기 임계값은 분포 교정 전 가설이다. 다음 단계에서 50~100개 참조 코호트를 구성해 단일 유형 30% 초과, 높은 차원 간 상관, 과도한 보류율을 확인한다. 임계값을 바꾸면 profile version을 올리고 기존 결과를 소급 변경하지 않는다.
