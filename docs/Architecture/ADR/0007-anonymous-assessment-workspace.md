# ADR-0007 — 익명 소유자의 평가 이력과 항목별 작업 공간

- 상태: Accepted
- 기록일: 2026-09-14
- 결정 주체와 근거: Astra, 사용자의 홈/프로필/항목별 분석 요청, [#13](https://github.com/SangJun-Pyo/MyAiScore/issues/13)
- 기록 성격: 사전 기록 (Phase 5 구현 착수 시)
- 대체 관계: 없음. [ADR-0003](0003-owner-and-public-boundaries.md)의 소유 경계를 확장한다.

## 배경

홈에 소개·평가 입력·예시를 모두 놓으면 반복 방문자가 자신의 평가를 찾기 어렵다. 사용자는 Tokscale처럼 영역을 나누고 프로필과 각 평가 항목을 설명하는 탭을 요청했다. MVP에 계정 로그인이나 개인 역량 인증을 추가할 필요는 없다.

## 결정

- 홈(`/`)은 반응형 3D 및 다섯 축 선택으로 제품을 소개한다. `/evaluate`는 평가 입력, `/profile`은 현재 소유자의 이력, `/insights`는 평가별 축 진단과 기준 설명을 담당한다.
- 프로필의 소유 기준은 기존 sessionStorage 토큰이다. 같은 브라우저 **탭**의 작업 공간이며 GitHub 계정 소유·신원·개인 전체 능력을 인증하지 않는다. 탭 종료/토큰 유실 시 복구할 수 없음을 안내한다.
- 인증 필수 `GET /api/assessments`는 현재 owner의 만료되지 않은 평가만 최신순으로 최대 50개 반환한다. 전체 수와 더 있음 여부를 함께 표시한다. 임의 owner ID를 조회 인자로 받지 않는다.
- 목록은 식별자, 저장소/SHA, 상태, 시각, 점수 상태/값, 축 코드/관찰 상태/레벨, 공개 여부만 허용하는 전용 DTO다. 근거·답변·발췌·자유 서술·소유 해시·토큰은 포함하지 않는다. 상세는 기존 소유 인증 endpoint에서 조회한다.
- 평가가 없으면 빈 상태다. 예시는 명시적 선택과 synthetic 표시를 유지하며 실제 이력에 삽입하지 않는다. 여러 프로젝트 평균을 개인 AI 실력으로 표시하지 않는다.
- API/모델/예산 미정인 이번 실제 평가 요청은 지정된 MyAiScore 공개 저장소를 SHA 고정해 수집하는 단계까지 진행한다. 모델 호출·질문 응답·점수 발급 완료를 꾸미지 않는다.

## 대안

로그인 기반 영구 프로필은 복구/여러 기기 접근에 유리하지만 인증과 데이터 수명 범위를 넓히므로 보류한다. 브라우저에 전체 결과를 복사하는 이력은 삭제·만료와 불일치할 수 있으므로 서버의 소유권 검사를 거친 목록을 사용한다. 한 페이지의 긴 섹션 구성은 소개에는 단순하지만 반복 사용을 지원하기 어려워 경로를 분리한다. 대안은 설계 검토이며 별도 실험 결과가 아니다.

## 결과와 재검토 조건

기존 소유 경계를 유지하면서 실제 평가의 진단을 다시 찾을 수 있다. 목록은 최대 50개이고 탭에 종속된다. 영구 계정·복구·페이지네이션 수요가 생기면 새 ADR과 계약으로 확장한다. 장식 3D 실패나 모션 감소 설정에서도 텍스트와 축 선택은 작동해야 한다.

## 근거와 검증 상태
