# ADR-0020 — 항상 표시하는 저장소 협업 유형과 신뢰도

- 상태: Accepted
- 기록일: 2026-09-19
- 결정 주체와 근거: 사용자의 `유형 판단 보류` 제거 요청, [Issue #49](https://github.com/SangJun-Pyo/MyAiScore/issues/49)
- 기록 성격: 구현과 함께 기록
- 대체 관계: [ADR-0018](0018-evidence-aware-collaboration-profile.md)의 유형 보류 정책을 v2.4에서 대체한다. v2.2·v2.3 저장 결과의 기존 보류 계약은 유지한다.

## 배경

v2.2·v2.3은 수집 제한, 희소 신호, 빈 차원, 여러 경계 차원 중 하나라도 있으면 네 글자 유형을 보류했다. 정직한 불확실성 표현이지만 사용자가 기대하는 결과 카드의 핵심 식별자가 사라지고, 실제 운영 저장소도 점수만 보이고 유형은 없는 경우가 많았다.

## 결정

새 분석은 `repository-signals-v2.4`를 발급하고 D/R·H/P·S/T·F/E 각 차원에서 항상 한쪽을 선택한다. 양쪽 강도가 같거나 모두 0이면 기존 결정론적 tie priority인 왼쪽 pole을 선택한다. 따라서 모든 정상 리포트는 네 글자 코드를 갖는다.

기존 보류 이유는 삭제하지 않고 신뢰도 맥락으로 유지한다. 고정 이유와 경계에 가까운 차원의 합이 없으면 높음, 하나면 보통, 둘 이상이면 낮음으로 화면에 표시한다. 수집 불완전·관찰 축 부족·실질 신호 부족·빈 차원·경계는 코드가 없다는 뜻이 아니라 가장 가까운 유형의 해석에 주의가 필요하다는 뜻이다. 신뢰도는 점수에 가산·감점하지 않는다.

strict parser는 v2.4에서 `assigned`와 유효한 네 글자 코드를 반드시 요구하고, 차원 강도·선택·주의 이유를 점수 신호에서 다시 계산한다. v2.2·v2.3 응답은 당시 규칙대로 `withheld`를 허용하고 재계산한다.

## 대안과 결과

- **보류 유지:** 불확실성 표현은 강하지만 결과 유형이 자주 사라지는 사용자 경험을 해결하지 못한다.
- **주의 이유 삭제:** 유형은 간단해지지만 빈 저장소의 tie-break와 충분한 근거의 분류가 같은 확실성으로 보이는 문제가 있다.
- **코호트 확률로 신뢰도 산출:** 아직 안정된 참조 코호트가 없어 이번 버전에는 이유 개수 기반의 세 단계만 사용한다.

이 유형은 저장소에서 보이는 상대적 신호 배치이며 사람의 성격, 실제 AI 사용 여부, 능력 등급을 뜻하지 않는다.
