# MVP Scope — v0.3.1

정본 허브: [`../00_MASTER_PLAN.md`](../00_MASTER_PLAN.md). PRD: [`PRD.md`](PRD.md).

이 문서는 이번 해커톤 MVP의 포함/보류를 확정하는 정본이다. 다른 문서(구현 작업 목록 포함)에서 여기 없는 기능을 필수로 되살리지 않는다.

## 포함 (Must Have) — 기능과 수용 조건

| # | 기능 | 수용 조건 |
|---|---|---|
| 1 | 공개 GitHub 저장소 URL 1개 입력 | GitHub 호스트 URL만 허용, 형식 검증 실패 시 명확한 오류 메시지. 개인 프로젝트 중심 — 저장소 소유자가 조직인 경우도 입력은 허용하되 팀 기여도 판정은 하지 않음을 안내. |
| 2 | 지원 스택 안내 | 기본안은 TypeScript/Next.js. 지원 범위를 벗어난 저장소(예: 미지원 언어 비율이 높음)를 감지하면 분석 전/중 제한 안내를 표시하고 부분 분석 또는 명확한 미지원 사유로 종료. |
| 3 | 로그인 없는 실제 분석 예시 | 최소 1개의 실제(또는 synthetic로 명시된) 예시 결과를 로그인 없이 열람 가능. 예시 데이터의 출처·생성 시점·"예시입니다" 표시 필수. |
| 4 | 커밋 SHA 고정 분석 | 분석 시작 시 대상 커밋 SHA를 확정하고 결과에 기록. 기존 assessment 재조회는 저장된 결과를 반환하며 새 모델 실행의 동일 점수를 보장하지 않음(수집 정책은 [`../Architecture/GITHUB_INGESTION.md`](../Architecture/GITHUB_INGESTION.md)). |
| 5 | 대표 AI 협업 사례 1개 + 선택적 근거 | 사례 없이도 분석 진행 가능(미확인 처리). 사례 제공 시 문제/제약/완료조건, AI 제안, 채택·거절·수정, 검증 결과 필드를 받음. 근거 연결은 선택. |
| 6 | 맞춤 질문 3개 | 질문은 해당 저장소의 실제 파일/구조/사례를 근거로 생성됨(범용 질문 금지). 미답변 시에도 결과는 나오되 해당 근거는 미확인으로 표시. |
| 7 | 확인/미확인 근거 표시 및 점수 발급·보류 | 다섯 축 모두 판정 가능하고 수집이 complete일 때만 총점 발급. 모든 결과 화면에 확인된 항목, 근거 ID, 미확인 사항, 점수 발급 또는 `withheld` 사유를 표시. 정책 정본: [`../Assessment/SCORING_RUBRIC.md`](../Assessment/SCORING_RUBRIC.md). |
| 8 | 개선 작업서 1건 | 가장 중요한 개선 행동 1개를 [`../Knowledge/IMPROVEMENT_TASK_TEMPLATE.md`](../Knowledge/IMPROVEMENT_TASK_TEMPLATE.md) 형식으로 생성하고 원클릭 복사 제공. |
| 9 | 선택적 공개 결과 페이지 | 기본은 비공개. 사용자가 명시적으로 선택할 때만 공유 가능한 URL 생성. 로그인 없는 결과도 관리 토큰으로 접근·삭제·공개 전환 가능([`../Security/PRIVACY_SECURITY.md`](../Security/PRIVACY_SECURITY.md)). |
| 10 | 동일 프로젝트 전후 비교 | 같은 저장소의 이전 평가와 새 커밋 평가를 나란히 비교. 종합 성장 대시보드나 시계열 그래프는 만들지 않음. |
| 11 | 실패·재시도·제한 초과·보류 상태 | 분석 실패, 저장소 크기/파일 수 초과, 속도 제한 초과, 점수 보류 각각에 대한 화면 문구와 재시도 경로를 정의([`../UI/USER_FLOW.md`](../UI/USER_FLOW.md)). |

## 보류 (Not MVP)

| 항목 | 이유 |
|---|---|
| Private 저장소, GitHub App 설치, 필수 GitHub 로그인 | 권한 연동 복잡도와 일정 제약. 공개 URL 입력만으로 핵심 가설 검증 가능. |
| 여러 저장소 종합 평가, 팀 기여도 판정 | 단일 프로젝트 심층 진단에 집중. 팀 기여도 판정은 별도 attribution 설계가 필요하며 근거 신뢰도 리스크가 큼. |
| Local Evidence Mode, CLI, IDE 플러그인 | 조작 가능성이 높고 검증 인프라가 없음. v0.2에서 다루던 로컬 프롬프트 방식은 이번 MVP 필수 문서로 복원하지 않는다. |
| 개인 기술 숙련도 등급, 채용 적합성 판정, 개인 역량 인증서, Verified 배지 | 제품이 보장할 수 없는 인증 약속이 되어 신뢰성 리스크가 큼. |
| 리더보드, 백분위, 소셜 기능, 조직용 평가, 학습 플랫폼 전체 | 초기 표본 부족, 점수 경쟁으로 변질될 위험. |
| 별도 Project Quality 총점과 Engineering Skill Profile 전체 | AI 활용 점수와 혼합되면 "좋은 코드=높은 AI 점수" 오해를 재생산. 필요한 프로젝트 관찰은 진단 근거로만 제공. |
| 서비스의 저장소 자동 수정·배포 | 실행 격리 원칙 위반. 개선은 사용자가 직접 적용. |

기존 v0.2 문서에 "필수"로 적혀 있던 항목이라도, 위 보류 목록에 있으면 이번 MVP에 다시 넣지 않는다. 공개 결과 페이지(#9)와 역량 인증서(보류)는 서로 다른 기능이다 — 전자는 사용자가 선택한 결과 공유, 후자는 제품이 부여하는 공식 인증이다.

## 일정 부족 시 축소 순서

남은 기간 안에 전체를 완성하지 못할 경우, 다음은 1번부터 먼저 검토할 축소 제안이다. 실제 범위 변경은 이유를 기록하고 사용자·Astra와 합의한 뒤 적용한다.

1. 동일 프로젝트 전후 비교 (#10) → 개선 작업서까지만 제공하고 재평가는 수동 안내로 대체
2. 선택적 공개 결과 페이지 (#9) → 비공개 결과만 제공(공유 링크 보류)
3. 맞춤 질문 3개 (#6) → 1~2개로 축소, 단 근거 연결 원칙은 유지
4. 실제 분석 예시 체험 (#3) → synthetic 예시 1개만 제공(실제 실행 예시 생략), 단 "예시" 표시는 유지
5. 지원 스택 안내 (#2)의 범위 감지 정교화 → 단순 확장자/설정파일 기반 휴리스틱으로 축소

축소하지 않는 항목(핵심 가설 검증에 필수): 커밋 SHA 고정 분석(#4), 확인/미확인 근거 표시 및 점수 발급·보류(#7), 개선 작업서(#8), 실패/보류 상태 처리(#11). 이 네 가지가 없으면 제품의 핵심 차별점이 성립하지 않는다.
