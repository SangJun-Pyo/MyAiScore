# Privacy & Security v0.3.1

정본 허브: [마스터 플랜](../00_MASTER_PLAN.md). 접근 계약: [API_DATA_CONTRACTS](../Architecture/API_DATA_CONTRACTS.md). 수집: [GITHUB_INGESTION](../Architecture/GITHUB_INGESTION.md).

## 1. 데이터 경계

공개 저장소만 분석한다. 공개 코드와 개인 협업 사례·대화 발췌·질문·답변·평가 결과는 서로 다른 공개 범위를 갖는다. 개인 자료는 기본 비공개이며 코드 저장소가 같다는 이유로 다른 사용자에게 반환하지 않는다.

공통 캐시는 공개 코드/정적 수집만 저장한다. 사용자 입력과 평가 결과는 owner 및 assessment 범위로 격리한다. 실제 레벨·프롬프트·모델 버전이 다른 개인 평가를 공통 repo 캐시에서 재사용하지 않는다.

## 2. 소유 권한과 공개

- 모든 비공개 읽기와 쓰기, 질문/답변, 처리·재시도, 비교에 서버측 소유 권한 검사를 적용한다. assessment_id만으로 접근할 수 없다.
- owner 토큰은 256비트 이상 랜덤, 서버에는 해시만 저장한다. 클라이언트 sessionStorage + Authorization 헤더로 사용한다. 로그·URL·공유 링크·오류에 넣지 않는다.
- service-role 키와 owner 해시는 클라이언트에 제공하지 않는다. 익명 브라우저가 DB를 직접 읽는 권한을 부여하지 않으며 서버에서 인증/인가 후 필요한 DTO만 반환한다.
- 공유는 done인 결과의 PublicResultDTO 미리보기 후 사용자가 선택한다. 원문 사례·발췌·질문 답변·owner 필드·비공개 비교 자료는 공개 DTO에 포함하지 않는다.
- 비공개 전환·삭제 즉시 공유 링크 무효화. 재공개 시 새 share_id. 민감한 응답과 공유 유효성 확인은 무분별한 CDN 캐시 대상이 아니다.
- 토큰 분실 복구는 MVP 범위 밖이다. 창 종료 등에 따른 sessionStorage 소실과 별도 안전한 보관 필요성을 명시한다.

## 3. 저장과 삭제 (기간은 운영 초안)

선정 코드 원문은 메모리/제한된 일시 캐시에서 분석하고 Assessment에는 필요한 요약·locator·hash를 저장한다. 공개 코드 원문 캐시 TTL은 24시간 기본안이며, 조회 시 현재 공개 접근을 재확인한다.

선택적 사용자 발췌 원문과 상세 LLM 디버그 원문은 기본 저장하지 않는다. 꼭 필요한 임시 원문은 접근 제한 하에 최대 7일, 개인 평가·요약 자료는 생성일 기준 최대 90일 보존 초안이다. 무기한 보관을 기본값으로 하지 않는다.

사용자의 삭제 요청 시 즉시 비공개/접근 차단하고 연결된 사례·답변·근거·비교·요약을 7일 이내 영구 제거한다. 공유 응답 캐시가 있다면 함께 무효화한다. 다른 평가의 비교는 삭제된 자료를 복제해 계속 노출하지 않는다. 운영 백업의 삭제 반영 시점은 배포 전 확정하고 안내한다.

삭제·기간 경과 정리는 실제 배포 시 실행 주체와 수행 기록을 갖춰야 한다. 문서의 보존 기간만으로 자동 삭제가 구현됐다고 주장하지 않는다.

## 4. 입력·출력 검사

URL·GitHub 호스트·리다이렉트·본문 크기는 GITHUB_INGESTION/API_DATA_CONTRACTS를 따른다. 사용자·저장소 텍스트가 가리키는 URL을 무조건 따라가지 않는다. 사용자 입력에는 결과 레벨/가중치/owner_id를 쓸 권한이 없다.

비밀 패턴은 LLM 전송 전 마스킹하고 .env/비밀키 파일은 기본 제외한다. 패턴 탐지만으로 모든 비밀을 찾아낸다고 보장하지 않는다. 사용자에게 민감한 원문 대신 필요한 발췌를 선택하도록 안내한다.

웹 출력은 텍스트/안전한 Markdown으로 렌더링한다. 사용자 HTML과 스크립트를 실행하지 않고 허용된 링크 scheme만 사용한다. 공개 요약에 원문 비밀이 다시 섞이지 않도록 출력 검사와 미리보기를 적용한다.

## 5. 프롬프트 인젝션과 실행 금지

외부 문서·주석·커밋 메시지·발췌는 평가 자료이며 시스템 지시로 승격하지 않는다. LLM에 셸·자유 네트워크·배포·저장소 쓰기 권한을 부여하지 않는다. 구조화 출력·근거 참조·locator를 검증한다.

고정 점수 공식과 JSON 형식만으로 조작을 막았다고 말하지 않는다. 공격이 축별 레벨을 부풀릴 수도 있으므로 [CALIBRATION_PLAN](../Assessment/CALIBRATION_PLAN.md)의 삽입 전후 사례를 실제 평가에서 확인해야 한다.

수집기는 제출 저장소의 install/build/test/lint/scripts/hooks/MCP를 실행하지 않는다. 테스트 파일 존재와 실행 성공을 분리하고, 사용자 제공 로그는 사용자 제공 근거라는 한계를 표시한다.

이 금지는 평가 대상 저장소를 실행하지 않는다는 뜻이다. 개발자가 MyAiScore 자체의 테스트를 실행하는 것까지 금지하는 것은 아니다.

## 6. 로그·남용 방지

로그에는 처리 식별자·단계·오류 코드·시간·바이트·요청 수를 남긴다. owner 토큰, 협업 사례/답변/발췌 원문, 서비스키, 전체 LLM payload는 평문 로그에 남기지 않는다.

인증된 owner별 요청/동시 실행 제한과 IP 기반 보조 제한을 적용한다. 익명 owner를 새로 만든다고 전체 제한을 우회하지 못하게 한다. 브라우저 지문 수집은 기본안에서 제외한다. 비용을 늘리는 공개 force_fresh 우회 기능을 만들지 않는다.
